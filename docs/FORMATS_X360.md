# Midnight Club: Los Angeles (Xbox 360) — распаковка и редактор треклиста

Запуск редактора: `run_gui.bat "<папка игры>"` (или `py mcla_gui.py "<папка игры>"`).
Папка игры = та, где лежат `default.xex` и `xarchive_*.rpf`. Оригинал никогда не меняется:
правки копятся «черновиком» (жёлтые строки), запись — только в НОВЫЙ файл/папку после подтверждения.

## Что умеет редактор (всё проверено в Xenia)
- перенос песни в другой жанр (перетащить на жанр слева, либо «Move to genre», либо правый клик);
- порядок внутри жанра (перетащить строку, «Move up/down», Ctrl+↑/↓); песни `SC` всегда идут после базовых;
- переименование названия (двойной клик / F2).   название приводится к ВЕРХНЕМУ РЕГИСТРУ. Запись текстового банка меняет длину (проверено в игре: 52 символа влезают), лимит 75 символов. Меняется во всех 6 языках;
- удаление песни из плейлиста: кнопка `Remove song` / Del / правый клик; удалённые песни видны в разделе `Removed` слева
  (вернуть: Revert / Backspace или перетащить на жанр). Последнюю песню жанра удалить нельзя. Объекты песни в game.dat остаются;
- предпросмотр / экспорт WAV (нужен ffmpeg: переменная `FFMPEG` или путь из `mcla_gui.py`);
- сборка: `Build cache.rpf...` (один файл ~2 ГБ — положить в игру вместо `xarchive_cache.rpf`) или
  `Build test game folder...` (папка с жёсткими ссылками на остальные файлы игры — для запуска в эмуляторе).
Замена/добавление АУДИО пока невозможны: нужен кодировщик XMA2 (см. ниже).

## Устройство данных
- `xarchive_*.rpf` — RPF3, заголовок LE, TOC с 0x800 зашифрован AES-256 (16 проходов ECB), ключ в `rpf3.py`.
  Имён нет, только joaat-хэши. Записи: `hash,size,offset,disk`. disk: бит31 = ресурс RSC5 (LZX), бит30 = raw-deflate.
- `cache.rpf`: `game.dat` (raw-deflate, BE): каталог объектов + объекты песен + менеджеры музыки;
  текстовые банки (dir 1b2d32db: a4c1e8fa/ac5297d5 — основные, da0b8b80/f5560436 — песни SC; копии идентичны).
- Песня = объект `GENRE_ARTIST_TITLE` с байтом жанра (Eclectic 0, Electronic 1, Hard Rock 2, Hip Hop 3, Rock 4,
  Techno 5, West Coast Rap 6) перед `hash(4) e3 8f cf 16 len 'Music_<Genre>_...'`.
- Менеджеры `MUSIC_0_MANAGER` (97 песен) и `MUSIC_0_MANAGER_SC` (+9): 7 групп подряд `[count][count x u32 BE joaat(объект)]`
  в порядке Hard Rock, Rock, Electronic, Techno, Hip Hop, West Coast Rap, Eclectic (группа может быть пустой).
  Список жанра в игре = песни менеджера (порядок массива) с нужным байтом жанра; базовые, затем SC.
  Правки хранят размеры объектов неизменными → каталог `game.dat` перестраивать не нужно.
- Названия: запись `hash(u32 LE joaat('Music_...')) 01 00 06 00 00 00 'nofont' nchars UTF-16LE 1.0f 1.0f 00 00`.
- Аудио: `xarchive_music.rpf` (и облегчённые копии в `audlo.rpf`): блоки 0x20000, два моно-потока XMA2 (L/R), последний
  пакет канала дублируется в начале следующего блока (при склейке отбрасывать). Имя файла = joaat(имя волны из sounds.dat).
  ВАЖНО: игра берёт список архивов `audlo+cache` или `audio+music+cache` — при замене аудио менять оба.

## Файлы
`rpf3.py` `aes_pure.py` `xex_unpack.py` `lzx.py` — форматы; `mcla_unpack.py` — распаковщик; `mcla_music.py` — треки → WAV;
`mcla_model.py` — модель редактора; `mcla_gui.py` — GUI; `cache_patch.py`, `rpf3_write.py` — запись в архивы;
`playlists.py`, `tracklist.py`, `gamedat.py`, `gxt.py` — разбор и отчёты (`playlists.csv`, `tracklist.csv`).
Тесты: `test_model.py` (загрузка → правки → сборка → перезагрузка).

## Замена аудио (добавлено 2026-09-19)
GUI: `Audio settings...` (путь к кодировщику XMA (.exe, совместимый по командной строке с Microsoft XMAENCODE), ffmpeg, качество 80 для music.rpf / 70 для audlo.rpf) → выбрать песню →
`Replace audio...` (любой файл, понятный ffmpeg) → `Build changed archives...` (папка) или `Build test game folder...`.
Кодировщик запускается только при сборке (левый и правый канал отдельными моно-файлами: `<кодировщик>.exe "x.wav" /Q 80 /T out.xma`; имя файла любое, например xmaencode.exe / xmaencode2008.exe; нужен вывод XMA1, xma2encode.exe пишет XMA2 и не подходит).
Собираются только изменённые архивы; music.rpf И audlo.rpf нужны оба (игра берёт audlo+cache или audio+music+cache).
Файл трека (`xma_track.py`, проверен пересборкой всех 108 оригиналов): заголовок файла; таблица блоков после него
(по 8 байт на блок: начало блока в семплах, 44100); начало первого блока = ceil((hdr+8*блоков)/0x800)*0x800;
два потока в порядке ВОЗРАСТАНИЯ id (id = joaat(<имя волны>_LEFT/_RIGHT); при замене берутся id оригинала);
блоки 0x20000: 62 пакета на оба канала, «отстающий» канал получает следующий пакет, «опережающий» повторяет последний
пакет в начале следующего блока; стыки блоков ставятся на границу кадра.
Ограничения: канал с цифровой тишиной кодируется кодировщиком необычно и сейчас не поддерживается планировщиком блоков;
сопоставление id → колонка (лево/право) ещё проверяется.

## game.dat / удаление песен (2026-09-19)

Перебор объектов game.dat — gamedat_rebuild.py (identity-пересборка побайтно точная). Менеджер может менять размер: Project.remove_song() убирает песню из плейлиста (проверено в игре), остальные объекты сдвигаются. Длинные названия проверены в игре. Новая песня требует объектов в sounds.dat (SND_*, GARAGE, EOR) — не сделано; у заменённого аудио остаётся старая заставка EOR.

## Новые песни (добавлено 2026-09-19)
GUI: `Add song...` (файл аудио, исполнитель, название, жанр) -> песня встаёт в конец списка жанра (можно переименовать, переместить,
удалить = отменить). Аудио кодируется и все записи создаются при сборке (`Build changed archives...` / `Build test game folder...`).
Что создаётся (`addsong.py`, шаблон = любая базовая песня того же жанра):
- `game.dat`: объект песни (id = смещение имени в таблице имён, хэш `SND_<объект>`, ключ `Music_<Жанр>_<Исп>_<Название>`) + запись в MUSIC_0_MANAGER;
- `sounds.dat` (`sounds_rebuild.py`): 6 объектов (SND_<объект>, SND_<жанр>_GARAGE_<имя> + по 2 слота волн), запись в GARAGE_MUSIC_MASTER,
  строка `MUSIC\<ИМЯ>` в таблице путей потоков (без неё звука нет);
- текстовый банк: ключ (в отсортированное место списка ключей) + запись в конец каждого из 6 языковых блоков;
- `music.rpf` и `audlo.rpf`: новый файл `joaat(<ИМЯ>)` в каталоге music (`rpf3_add.py`, места в оглавлении: ~15 / ~66).
Ограничения: у новой песни нет заставки конца гонки (EOR_*), клонировать/добавлять можно только в базовый менеджер (не SC),
не больше ~15 новых песен (свободные места в оглавлении music.rpf). Проверено в игре: клон существующей песни играет.

## Важно для реальной консоли (2026-09-19)
У каждого повторённого (dup) пакета skip > 0 (в оригиналах 5818/5818); skip = 512*кадры + delta, delta = T//100000 для опережающего канала. Раскладка с delta=0 на очень регулярных данных давала dup со skip=0 - Xenia это не замечает, а настоящая консоль отключает такой поток с первого же блока (замеры OBS). Теперь xma_track.build_track использует delta по умолчанию; готовые папки можно исправить без перекодирования: py relayout_tracks.py <папка>.

## Гараж и заставка конца гонки у новых песен (2026-09-19)
Объекты EOR_<ИМЯ> (+2 слота), запись в EOR_<ЖАНР>_RAND, строка SPECIAL_EFFECTS_STREAM\EOR_<ИМЯ>, файл 30 с (первые 30 секунд песни, затухание 1,5 с) в audio.rpf и audlo.rpf (каталог 8fd900e5). Создаются автоматически при добавлении песни (настройка eor). Тестовая сборка с усиленными весами: hw_test\build_hw_eor.bat. Проверено офлайн; на консоли ещё нет.

## Музыка на тусовках (2026-09-29)
12 случайных списков HNG_LM_<район>_<LOCAL|WAGER>_HANGOUT*_MUSICSHOT_MASTER в sounds.dat играют одни и те же 6 отрывков - файлы `HNG_LM_MUSIC_<ANTIFORM|DRIVINGDOWNTHEBLOCKHANGOUT|GETCOOL|JMILL|RANDOMLUCK|TECHN9NE>` только в `xarchive_audio.rpf`, каталог 01a2e516 (AMBIENCE_LANDMARKS). Формат (`xma_single.py`, все 6 оригиналов собираются байт в байт): один моно-поток XMA1, 48 кГц, блоки 0x8000.
- заголовок файла: `[0, H, блоков, 0x8000, 0, 0, 0x30, 0, H, 1, 0, первый блок]` + запись потока `[0, 0, id, размер секции]`;
- секция потока: `[0, 0, id, пакетов*0x800, всего сэмплов, ffffffff, 48000<<16|ff5f, 0, 0, 0x38, 0, 0, 0, пакетов]` + таблица `[0] + 512*(кадров завершено+1)` для всех пакетов кроме последнего;
- после заголовка таблица `(начало блока, 48000)` на каждый блок, выравнивание до 0x800;
- блок: заголовок 0x800 `[0, 0x18, 0, 0x28, 0, 0x28, 0, пакетов, skip 0, сэмплов] + [база] + пары (c-1, c) + [конец-1]`, затем 14 пакетов (в последнем меньше); концы блоков на границах кадров, повторённых пакетов нет. Хвост заголовка за таблицей - байты заголовка предыдущего блока (так делал инструмент игры).
Кроме того, `rpf3_rebuild` теперь принимает ключ замены `(хэш каталога, хэш файла)`: в audio.rpf/audlo.rpf 57 хэшей файлов встречаются в двух каталогах (а каталоги 6d155a1b и 1c2b2213 - по два раза под разными родителями), `rpf3.Entry.parent` - хэш каталога записи.
